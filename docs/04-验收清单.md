## 二、页面验收（各页面占位文件里已列出自己的编号项）

B 番剧库（views/anime，占位页含 F01–F10）：搜索 300ms 防抖命中中文名/日文名/制作公司、标签+年份+状态组合筛选、三种排序、8 条/页分页且越界回第 1 页、筛选条件写进 URL query、列表/海报双视图只切 class 不重新取数、详情弹窗不跳路由、空结果空态、卡片强调色来自 token。

E 个人中心（views/profile）：资料卡与编辑、四张统计卡、状态环图 / 评分柱图 / 标签条形 / 月度热力（纯 SVG/CSS）、重置演示数据（二次确认）、数字与手帐页一致。

## 三、通用验收

### 功能与边界
- [ ] 表单空提交、超长输入、非法字符都有明确提示
- [ ] 直接改 URL 到不存在的手帐/帖子 id → 友好空态或回列表，不白屏
- [ ] 未知路由重定向 `/library`
- [ ] 未登录访问内页 → 登录页，登录后回跳原页
- [ ] 手帐进度 = 0 或 = 总集数时文案正确（未开始 / 全 N 集）

### 响应式
- [ ] 375 / 768 / 1024 / 1440 四个宽度无横向滚动
- [ ] 移动端底部 TabBar 不遮内容
- [ ] 海报墙 4 → 3 → 2 → 1 列降级正常

### 无障碍
- [ ] 所有交互元素可 Tab 到达，焦点可见（3px 珊瑚描边）
- [ ] 图片有 `alt`，装饰图 `alt=""`
- [ ] 表单 label 与 input 关联（`id` / `for`）
- [ ] 对比度：墨黑文字在五色底上都达标
- [ ] `prefers-reduced-motion` 下关掉位移动画

### 性能
- [ ] 路由懒加载（`() => import()`），首屏不加载全部页面
- [ ] 产物 gzip < 500KB；单张海报 < 120KB
- [ ] 列表页无 N+1 式重复取数（切视图不重新查库）

## 四、答辩三问，提前准备

1. **为什么数据层要单独一层？** —— 四个页面共用一份数据，读写收在一处；换存储只改 db.js；页面不碰 localStorage，避免各自写各自的键导致状态打架。
2. **刷新保持登录怎么做的？** —— session 存 `userId + expiresAt`，「记住我」7 天否则 12 小时；应用启动时 `restore()` 校验过期并同步 Pinia；路由守卫读 Pinia，未登录带 `?redirect=` 回登录页。
3. **统计数字为什么三个页面一致？** —— 口径写死在 `useStats()`，页面只渲染不计算；平均分只算已打分条目，已看完只算 `status === '看过'`。
