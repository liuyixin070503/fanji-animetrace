# 03 · 协作制度

> 5 个人、28 天、一个纯前端项目。制度只为两件事：**别互相踩**、**别一起卡住**。

## 一、房间制（最重要的一条）

一人一间屋，只改自己屋里的东西：

| 人 | 可以改 | 绝对别碰 |
| --- | --- | --- |
| A 组长 | `package.json` `vite.config.js` `eslint.config.js` `src/router/` `src/styles/` `src/types/` `src/data/` `src/stores/` `src/composables/` `src/components/ui/` `src/components/layout/` `src/App.vue` `src/main.js` | B/C/D/E 的 views（除集成修复） |
| B | `src/views/anime/AnimeLibraryView.vue` | 其它一切 |
| C | `src/views/journal/JournalView.vue` `JournalEditView.vue` `JournalDetailView.vue` | 其它一切 |
| D | `src/views/forum/ForumListView.vue` `PostCreateView.vue` `PostDetailView.vue` | 其它一切 |
| E | `src/views/profile/ProfileView.vue` | 其它一切 |

B/C/D/E 在视图里需要新样式？**写在自己文件里的 `<style scoped>`**，不要往 styles/ 加。
需要新组件、新工具函数、新 db 函数 → 提需求给 A，**24 小时内必有答复**（给实现、给替代方案、或明确拒绝并说明理由）。

## 二、分支与提交

```
main                  ← 只有 A 合并，永远可运行
feat/<角色>-<页面>     ← 例：feat/B-library
fix/<角色>-<问题>      ← 例：fix/C-progress-overflow
```

- 从最新 `main` 切分支，一个分支只做一件事。
- 提交信息：`<角色>: <动词> <对象>`，例：`B: 实现番剧库筛选与分页`、`A: 补 db 迁移与 resetAll`。
- 一个 commit 别混「功能 + 格式化」；先 `npm run lint:fix` 再提交。
- **禁止** force push `main`、禁止直接 push `main`。

## 三、节奏

| 时间 | 事 | 产出 |
| --- | --- | --- |
| 每天 20:00 前 | 各自在本群发一句：今天做完什么 / 明天做什么 / 卡在哪 | 一句话，不用长 |
| 每周一 20:00 | 站会 15 分钟 | 本周目标 + 谁在等谁 |
| 每周三 | A 做代码 review，把问题写成 issue 列表 | review 结论 + 待办 |
| 每周日 | 合并 `main`、打 tag `v0.x`、部署一版演示 | 可点的线上地址 |

**评审看四件事**：能不能跑（`npm run lint` 0 error）、有没有绕 db.js、有没有写死颜色/尺寸、移动端 375px 会不会炸。

## 四、接口冻结（11-27）

- 11-27 之后 `src/data/db.js` 的函数名、参数、返回值**不再改**。
- 要加字段？加，但要通知全组（群里 @all + 一句话）。
- 要改签名/删函数？发 RFC（RFC）：背景 / 现状 / 提议 / 影响谁 / 迁移步骤，A 24 小时内批复。
- 冻结不是「不许动」，是「动之前先说话」。

## 五、集成日（12-08 19:00）

流程固定，别自由发挥：

1. 全员先 `git pull`，`npm install`（A 若改过依赖）。
2. 打开页面 → 个人中心「重置演示数据」→ 从零走一遍全链路：
   注册 → 登录 → 番剧库筛选 → 导入到手帐 → 编辑手帐 → 发帖 → 评论 → 点赞 → 看个人中心图表 → 退出。
3. **只记录问题，不现场改代码**（现场改会把别人的分支搞乱）。写进 issue 列表，标 P0/P1/P2。
4. 散会后各自修自己屋里的 P0，A 修公共件的。

## 六、卡住了怎么办

- 卡 30 分钟没进展 → 立刻在群里说「我在做 X，卡在 Y，试过 Z」，不要闷头两小时。
- 只有 A 能改的文件出问题 → 找 A，别自己改。
- 两个人要改同一个文件 → 停手，A 决定谁改、另一个等。
- 某人请假 → 备份矩阵顶上：A↔C、B↔D、E 由 A 兜底。备份不是「帮他写」，是「保证这周能合」。

## 七、日志与周报模板

每日（群里一句话）：


每周周报（周日，四行）：

```

```

## 八、Issue 模板

```
标题：[页面] 一句话现象
现象：点了什么、看到什么
复现：1. 2. 3.
期望：应该怎样
环境：Chrome 版本 / 屏幕宽度 / 是否登录
截图：有就贴
优先级：P0 阻断流程 / P1 影响体验 / P2 打磨
```

## 九、常见摩擦与处理

| 摩擦 | 处理 |
| --- | --- |
| 公共组件不好用，想改 | 提需求，A 改；不要在自己文件里复制一份改 |
| 觉得别人的页面丑 | 提 issue 说清哪里不对，不直接改别人文件 |
| 数据对不上（统计数字不一致） | 一律用 `useStats()`，口径写死在 docs/02 |
| 合并冲突 | 冲突文件是谁的屋谁解；解完在群里说一声 |
| 进度落后 | 砍功能不砍质量：先保主链路（登录→库→手帐→论坛→个人中心） |
